Technical Summary

Architecture Summary For Technical Reviewers

This platform uses one reusable AI/ML backend pipeline for multiple decision models. A model workflow is selected through metadata and contracts, not separate page logic. The live server exposes a lightweight API surface for view-model data, model execution, simulation, run history, stage evidence, artifact download, inference contracts, and metrics.

The orchestrator is the control point. It reads the selected model contract, runs the eight-stage data and ML flow, writes deterministic artifacts under the run directory, and registers the result for later comparison. This keeps the standalone build simple while still making lineage, validation gates, model metrics, and activation outputs inspectable from the UI.

Enterprise integration hardening is deliberately profile-driven. Integrations such as MLflow lineage, Feast-style feature store artifacts, Splink identity evidence, Airflow metadata, Keycloak readiness, monitoring summaries, and Prometheus metrics can be shown without forcing those heavier services into the default standalone path.

Enterprise Integration Profile exposes optional lineage, feature-store, identity, orchestration, and access-control readiness while the default runtime stays standalone.
